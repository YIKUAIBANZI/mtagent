## 1. Background

### 1.1 v2.5 末实测耗时（map-view session 末）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| Profiler LLM | 3.6s | 9% |
| Planner compose 单次大 LLM call | 32.5s | 84% |
| amap transit_segments + 其他 | <2s | 5% |
| **总 wallclock（warm）** | **38.6s** | **100%** |

赛题硬门槛 < 10s。本 spec 目标 **≤ 20s（warm）**，承认未达硬门槛，prompt 瘦身 / 候选 POI 砍 top-N 留 v1.6.1。

### 1.2 体感问题（v1.5 ship 后用户反馈）

**问题：Planner 一次性大 prompt（候选 POI 60+ × N 天 + 大 JSON 输出 schema）让 LLM 等返回 ~32s。期间 SSE 完全没事件，`compose_start` 之后死寂 32s 直到全部 day_done 一齐喷出。这是 demo 最大体感问题——不是慢，是「卡死然后突然出来」。**

用户原话：「a 肯定要有一直能看到进展，结合 b 每天的内容分开三次输出。用户不会觉得等了 50s 而是 3 个十几秒，而且流式输出也会弱化用户在等待的一个想法。」

### 1.3 地图视图体感问题（map-view session 末）

map-view UI 已让前端聊天侧拿到流式 chat bubbles + place cards，但**地图侧 markers 仍要等 `trip.complete` 整批一次性落**——原因是 `planner.day_done` SSE event payload 不含 lat/lng 坐标，前端拿不到 per-day 坐标。

**用户期望：聊天写到 day 1 完成时，地图上 day 1 的 4 个 pin + 路线已经落好；写到 day 2，第 5-7 个 pin 接着落。**

### 1.4 解决方向

A. **Per-day 独立 LLM call + asyncio 并发**——单天 prompt token 数降到 1/3-1/4，3 天 max ≈ 单天耗时 ~15s
B. **`day_done` SSE event payload 加 stops 坐标 + per-day transit_segments**——前端按事件流分天落 markers + 算 polyline
C. **混合字符流：`planner.day_partial` 仅 emit stops name（不 emit 坐标），聊天侧 day card 文字浮现；地图侧仍等 `day_done` 整批 drop markers**——保留地图动画爆发感

## 2. Goals (v1.6 交付能力)

| # | 能力 | 验收点 |
|---|---|---|
| 1 | **每天独立 LLM call** | `Planner.compose_one_day(day_idx, ...)` 抽出；单天 prompt 只含本日 anchor + 该日聚类 POI |
| 2 | **N 天并发执行** | N 次 LLM call 用 `asyncio.gather` / `as_completed` 并发；`asyncio.Semaphore(3)` 限并发（防 dashscope 限速） |

## 5. 核心设计

### 5.1 `compose_one_day` 签名

```python
async def compose_one_day(
    self,
    day_idx: int,
    anchor: POI,
    day_cluster_pois: list[POI],   # 本日 anchor 周边聚类（5-15 个）
    intent: ParsedIntent,
    template: dict,                 # generate_day_template[day_idx]
    pace: str,
    on_partial: Callable[[int, list[str]], Awaitable[None]] | None = None,
) -> tuple[int, DayPlan, list[dict]]:
    """
    Returns (day_idx, day_plan, transit_segments).

    on_partial(day_idx, names_so_far): 字符流增量解析回调（混合 C 方案）。
    LLM 失败时抛 PlannerLLMError，上游降级到 _synthesize_fallback_route。
    """
```

**实现：**
- 单天 LLM 用 `stream=True`，逐 chunk 累加 `buf: str`
- 每收 chunk 跑 `_parse_partial_stops(buf)`：宽容 regex 提 `"name": "..."` 累积 list，长度增加就 await `on_partial(day_idx, names)`
- 最终 buf 完整 `json.loads` → 落 DayPlan
- 调 `amap.get_transit_segments(day_plan.stops)` 算 transit_segments（async，1-2s）
- return `(day_idx, day_plan, transit_segments)`

### 5.2 单天 prompt 结构

```
你是行程编排助手。请为 {city} 第 {day_idx+1} 天编排路线。

约束：
- anchor: {anchor.name}（{anchor.latitude}, {anchor.longitude}）
- traveler_type: {intent.traveler_type}
- pace: {pace}
- budget_level: {intent.budget_level}
- 当日 day template:
  {json.dumps(template['slots'])}

候选 POI（仅本日 anchor 周边 5km 已聚类）：
{poi list with openshopid/name/categories/star/avgprice/business_hour}

输出 JSON：
{
  "stops": [
    {"poi_openshopid": "...", "slot_name": "上午景点"},
    ...
  ]
}
```

**Token 数对比：** 旧大 prompt ~6k 输入 + ~2k 输出 → 新单天 prompt ~1.5k 输入 + ~600 输出（**1/4 大小**）。

### 5.3 增量字符流解析（`_parse_partial_stops`）

```python
import re
_NAME_RE = re.compile(r'"name"\s*:\s*"([^"]+)"')

def _parse_partial_stops(buf: str) -> list[str]:
    """Return stop names extracted from incomplete JSON. Tolerates unterminated buffers."""
    return _NAME_RE.findall(buf)
```

**为什么不解 lng/lat：** JSON 通常按字段顺序输出，name 字段先到；坐标要等 POI 字段全到才可信。day_done 整批送坐标足够。

**容错：** regex 不抛错。garbage 输入返回 `[]`。

### 5.4 并发 & 顺序 yield

```python
# in routes.py compose 段
sem = asyncio.Semaphore(3)
partial_queue: asyncio.Queue = asyncio.Queue()   # 无界，3 天 trip max ~20 partial events

async def _wrap(d):
    async with sem:
        return await planner.compose_one_day(
            day_idx=d, anchor=anchors[d], day_cluster_pois=ranked_clusters[d],
            intent=intent, template=templates[d], pace=pace,
            on_partial=lambda di, names: _emit_partial(di, names),
        )

tasks = [asyncio.create_task(_wrap(d)) for d in range(intent.days)]

# on_partial 走 asyncio.Queue 反推 emit
async def _emit_partial(day_idx, names):
    await partial_queue.put(("planner.day_partial", {"day_idx": day_idx, "names": names}))

# 并发等所有 task + 串行 yield day_done
done_results: dict[int, tuple[DayPlan, list]] = {}
async for fut in asyncio.as_completed(tasks):
    try:
        d, dp, segs = await fut
    except PlannerLLMError as e:
        d = e.day_idx
        dp = _synthesize_fallback_route(templates[d:d+1], anchors[d:d+1], ranked_clusters[d:d+1], intent)[0]
        segs = await amap.get_transit_segments(dp.stops)
        yield format_event("planner.day_done_fallback", {"day_idx": d, "reason": str(e)})
    done_results[d] = (dp, segs)
    # 排空 partial queue
    while not partial_queue.empty():
        ev_name, ev_payload = partial_queue.get_nowait()
        yield format_event(ev_name, ev_payload)
    # emit day_done
    yield format_event("planner.day_done", {
        "day_idx": d,
        "day_plan": dp.model_dump(),
        "stops": [{"name": s.name, "lng": s.lng, "lat": s.lat,
                   "openshopid": s.openshopid, "slot_name": s.slot_name} for s in dp.stops],
        "transit_segments": segs,
    })
    # emit rationale (v1.5 既有)
    yield format_event("planner.rationale", build_rationale_for_day(dp, day_idx=d, stage="compose"))
```

**乱序问题：** `as_completed` 按完成时间。前端已用 `data-day` 索引 + `pendingDayRationales` map 处理乱序（map-view session 验证过），**不动前端排序逻辑**。

### 5.5 前端 SSE handler 改动

```js
// plan_stack.html (示意)
const dayMarkers = new Map();      // day_idx -> AMap.Marker[]
const dayPolylines = new Map();    // day_idx -> AMap.Polyline[]

case 'planner.day_partial': {
  const { day_idx, names } = ev.data;
  // 文字浮现：覆盖式 reorder day card 内 stop 行
  renderDayPartial(day_idx, names);
  break;
}

case 'planner.day_done': {
  const { day_idx, day_plan, stops, transit_segments } = ev.data;
  // 1. 落 numbered markers（动画延时）
  stops.forEach((s, i) => {
    setTimeout(() => dropMarker(day_idx, i, s.lng, s.lat, s.name), i * 120);
  });
  // 2. 算 polyline (per-segment per-mode)
  drawPolylineForDay(day_idx, stops, transit_segments);
  // 3. 更新 totals chip
  updateTotalsChip(transit_segments);
  break;
}

// trip.complete 时 fitView 累计所有 stops（已存在）
```

### 5.6 关键设计权衡

| 决策 | 选择 | 原因 |
|---|---|---|
| 字符流增量字段 | 只 emit name（不 emit 坐标） | name 在 JSON 早期到；坐标等字段全到 |
| 地图 marker drop 时机 | day_done 整批 drop（不在 partial drop） | 视觉冲击保留；坐标可信时机 |
| transit_segments 算时机 | 单天 LLM 完后串行算 | 简单；3 天累计 +3-6s 仍在 20s 内 |
| Semaphore 限并发 | 3 | dashscope 60 RPM 防护；N>3 时排队但不丢 |
| asyncio.gather vs as_completed | as_completed | 边完成边 yield day_done，体感更流式 |
| 旧 compose() 签名 | 保留 | 兼容 v0 入口测试 |

## 7. Error Handling & 降级

### 7.1 LLM 单天失败

```python
class PlannerLLMError(Exception):
    def __init__(self, day_idx, original):
        self.day_idx = day_idx
        self.original = original
        super().__init__(f"day {day_idx} LLM fail: {original}")

# 在 compose_one_day 内 catch (TimeoutError, OpenAIError, json.JSONDecodeError):
#   raise PlannerLLMError(day_idx, e)
```

上游 routes.py 在 `async for fut in as_completed` 内 catch `PlannerLLMError`：
- 走 `_synthesize_fallback_route([template], [anchor], [cluster], intent)` 单天合成
- 调 `amap.get_transit_segments(stops)` 仍算 transit
- emit `planner.day_done_fallback { day_idx, reason }`——前端用这个 marker 标记该天为 fallback 来源（灰色 icon 或 tooltip）
- 然后照常 emit `planner.day_done` + rationale（payload 一致，前端渲染路径统一）

**为什么发两个 event 不合并：** 前端需要区分 AI 编排 vs fallback 合成（UX 标记不同），但又要走同一个 marker drop / polyline 渲染路径——拆 event 让前端 UI 状态机简单。

### 7.2 fallback 坐标来源

`_synthesize_fallback_route` 直接从 `ranked_clusters[d]` 取 POI 对象，**lng/lat 字段本来就有**（POI schema 字段）。day_done payload 含 stops 坐标对 fallback 路径 free。

### 7.3 字符流解析失败

- `_parse_partial_stops(buf)` 用宽容 regex，不抛错
- 解析为空 / 长度不增 → 跳过该次 on_partial
- 即使整个 stream 字符流崩溃，最终 buf `json.loads` 失败 → 走 7.1 路径降级

### 7.4 dashscope 限流

- `asyncio.Semaphore(3)` 阻止 N>3 同时调用
- 单调用 OpenAIError (rate limit) → 上游 retry 一次（exponential backoff 1s），再失败走 7.1

### 7.5 前端 SSE 错误

- 收到未知 event type → 忽略（v0/v1 既有兜底）
- `day_partial` names 增量覆盖渲染：用 names list 作为单一 source of truth 重 render，不依赖到达顺序
- `day_done` 收到 lng=null/undefined 的 stop → 跳过该 marker，warning console（不该发生但兜底）

### 7.6 关键不变量

- ❗ **121 PASS baseline 不破**（map-view session 已建立）
- ❗ **`DayPlan.transit_segments: list[dict] = Field(default_factory=list)`** 不改（v2.5 持久化字段）
- ❗ **Wander 8 浮动 SVG 不删**
- ❗ **/map 旧页保留**（nav 入口仍在）
- ❗ **v1.5 rationale path 完全不动**（stage='compose' / day_idx）
- ❗ **旧 SSE 事件名全部保留**（profiler.* / planner.compose_* / planner.rationale / transit.updated / trip.complete）
