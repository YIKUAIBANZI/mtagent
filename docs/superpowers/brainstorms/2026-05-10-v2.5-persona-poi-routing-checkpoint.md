## 1 · 已决定（4 项）

### Q-1 / scope = D：直接深入 v2.5 spec
不重做 v1.6 性能方案，也不先排完整 28 天优先级。原因：v2.5 一招打三家（性能 + 个性化 + 创新性），ROI 高于单独 v1.6。

### Q-2 / 标的方法 = d：UGC 启发 + LLM 批量混合
- 强信号靠 UGC reviewTag / 评论文本启发（"亲子" "约会" 高频 → 直接落标签）
- 剩余靠千问批量离线 prompt 补齐
- **离线 pipeline 不堵主流程关键路径**（用户原话："数据处理不着急"）

### Q-3 / 用户画像分类 = D：traveler_type 主轴 + 4 个二元修饰符
- 主轴保留现有 6 类 `TravelerType`（情侣/家庭亲子/银发/独行/商务/朋友团）—— 不破坏 codebase + 95 测试
- 加 4 个二元修饰符提升表达力
- 故事最好讲："同样家庭亲子，偏文化去陕博、偏拍照去大唐不夜城"

### Q-4 / 修饰符 = a：4 个二元字段

| 修饰符 | true 含义 | UGC 信号 | Planner 杠杆 |
|---|---|---|---|
| `轻量体力` | 步行 ≤ 3km/天，避大量楼梯 | "带老人/带娃/累/走不动" 高频 | 不排"爬山/长距离徒步" |
| `重文化` | 愿意博物馆/古迹深度逛 ≥ 1.5h | "讲解员/历史/涨知识" 高频 | 陕博、碑林优先 |
| `重美食` | 一天 ≥ 2 顿正餐 + 1 网红小吃 | "好吃/必吃/排队也值" 高频 | 永兴坊、回民街优先 |
| `怕排队` | 排队 > 30 min 直接弃 | "排队太久/等了 X 小时" 负面高频 | 工作日错峰、避网红打卡点 |

设计原则：互相正交 / 能从 UGC 抽 / 对 Planner 有真杠杆 / **`怕排队` 直接对应赛题原话"想吃好又不想排队"**。

## 2 · 待决问题（5 项，下次接着）

### Q-5 / UGC 怎么启发抽信号
- mock 数据 UGC 长啥样还没看（先扫一遍 `data/mock_dianping/西安.json` 的 `ugc` 字段 + `reviewTags`）
- 启发规则形式：关键词频次阈值 / TF-IDF / 简单情感分类 / 多种叠加？
- 落地输出：`{poi_id: {modifier: confidence}}` 还是 hard true/false？

### Q-6 / LLM 批量标的 prompt 设计
- 输入字段：POI 名 + 类型 + top reviewTags + 评分？是否含评论文本片段？
- 输出 schema：JSON `{traveler_types: [str], modifiers: {bool}}`？
- batch 大小 / 并发 / 千问限流 / 重试策略
- 总成本估算（2400 POI × 1 call ≈ ~$5-10）

### Q-7 / 运行时怎么用
- 三种模式：
  - **a.** 硬过滤（filter）：traveler_type + 修饰符不匹配的 POI 直接踢
  - **b.** 软加权（ranker）：匹配的加分，不匹配的减分但保留
  - **c.** 二阶段：先 filter 主轴，后 ranker 修饰符
- 多方案对比要不要做？同 query 给"情侣版" + "家庭版"两套
- 推荐 c

### Q-8 / 召回不足兜底
- 标签太严会让某些组合（"商务+西安+三天+轻量体力+重文化"）召回 0 命中
- 兜底策略：依次松绑修饰符 → 松绑 traveler_type → 退回 v2 全池
- 阈值：每个 day 至少 N 个候选

### Q-9 / Profiler 怎么抽修饰符
- 用户输入"带长辈小孩五人西安三天预算 6000" 怎么抽出 `轻量体力=true`？
- 在现有 Profiler prompt 里加 schema 字段？还是新加一个 ModifierExtractor agent？
- 默认值策略：抽不出时按 traveler_type 推断（如 银发/家庭亲子 → `轻量体力=true`）
